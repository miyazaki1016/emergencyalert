# 実更新メールの本文生成互換性（A）の検証

既存Draft PR #155 / Issue #154の継続。既存collect.ts、generateMail、generateEmlを使用し、本文生成器・本番Edge・DB・cronは変更しない。個別本文、ID、事件詳細、住所、座標、認証値、生MIMEはGitへ保存しない。

## 判定

**広島：実更新メールの本文生成互換性PASS（A）。実旧DBによる更新判定・変更項目検出（B）は未検証。**

Gmail本文検索 `"広島県警アラート（更新）"` を日付制限なしで実行し、100件×5ページ＋91件の計6ページ591通、次ページなしまで確認。件名に更新を要求していない。include_raw_mimeで全591通のRFC822 base64urlを読み取り、全通text/plain・UTF-8・8bitを確認した。8bit本文の元バイトとUTF-8再生成本文を比較し、通常のbody表示をバイト比較に流用していない。全通が実更新通知で、対象外メール0通、取得/パース失敗0通。

|---|---:|---:|---:|
| 発見・原本取得 | 530 | 61 | 591 |
| 現在公開JSONと同じID | 0 | 24 | 24 |

不審者は59の異なるIDに対する61通（同IDの複数更新も個別に検証）。犯罪は530の異なるID。2026年の検索結果26通はすべて不審者（うち公開ID一致21通）。残りは2025年の不審者35通・犯罪530通。検索範囲を2026-11-04だけに限定した前回の未発見結果とは区別する。

**567通は公開実データとの完全一致認定の対象外だが、当時の実メールに記録された値による生成互換性Aの検証対象に含めた。** 公開現在値による一致24通と、当時のメール記載値による一致591通を同じ証拠として扱わない。公開IDがないことを本文不一致として数えない。滋賀の実更新メールは接続先切替待ちで今回0通・未検証。

## 仮旧値と検証範囲

実原本の各フィールド行と末尾の「●更新」を解析し、印付き項目だけ現在値と必ず異なる合成文字列、印なしは同じ値を入れたpreviousを生成。既存generateMail()へ渡し、**更新マークを削除して比較せず**再生成した更新本文そのものを比較した。更新見出し、末尾の●、全項目・順序・注釈・全角空白・市町名・署名・URL・本文末尾が比較対象。印の位置異常、未認識印、項目欠落・重複は拒否する。

公開同IDがある24通はcollectorの現在値と市町/署参照を使用しても全バイト一致。残りはメール本文の当時値と参照名を抽出。広島不審者resolutionは表示ラベルから描画等価のコードを構成する。空表示から元のnull/空文字/その他コードは特定できないため、復元したと主張しない。

Aは観測した変更項目の組み合わせを同じ形式で描画できることの証明であり、観測マーク自体の正当性を独立に検証するものではない。更新前SQL Server、当時の公開JSON、当時の比較状態はない。**B、新規/更新の選別、座標のみ変更時の送信判定、送信対象件数の再現は未認定**。犯罪メールの更新印は緯度493通・経度75通（重複あり）に観測されたが、その存在からplan()の送信判定を変更しない。

## 公開から消えたIDの調査

今回のcollectorは広島6,089件（不審者454・犯罪5,635）を正常取得。IDがない567通はSupabaseの既存recordsにも同IDがなかった。DBはID存在数のみ照合しpayloadの完全一致は今回の認定対象外。

不審者の公開発生日期間は2025-11-05〜2026-11-02、欠落37通の当時発生日は2025-03-02〜2025-10-27。期間外の古い情報が公開対象から外れた可能性と整合するが、削除理由の確証はない。

犯罪の欠落530通の発生日は2025-01-29〜2025-08-18で、現在犯罪JSONの発生日期間（2020-11-01〜2026-11-01）内にあるため、単純な期間外では説明できない。旧IDを部分文字列として含む現在IDは8通分で見つかったが、発生開始/終了日時・市コード・町域・カテゴリの同時一致は530通とも0件。ID変更・再掲・削除・仕様変更のいずれかは確定できず、類似IDを同じ事案と扱わない。旧JSONや提供元の履歴がないため理由は未確定のまま記録する。

## 実装・再現

既存scripts/jaspic-verify-real-mail.tsを拡張し、scripts/jaspic-update-observation.tsへ検証用入力の抽出・仮旧値構成を分離。--observed-updatesではメール記載値によるAと公開ID/現在値一致を別集計する。ネットワーク・SMTP・DB書込み機能はない。原本とcollector Item配列はGit外の一時領域だけに置く。出力は集計のみ、入力詳細は例外へ表示しない。

## 型チェックとテスト

変更前head a89958c時点で全体tscの出力を確保し、変更後と比較。既存15件（handler.test.ts 6、mail.test.ts 2、mime.test.ts 5、state.test.ts 2）の診断が同一。原因は異なるJSON fixture形状がunionに推論され、他種別の未定義項目がoptional undefinedとなる一方、RecordDataはstring|nullのみを許すこと。テストのfixture入力の静的型に限る不整合で、ランタイムテスト失敗ではない。今回の変更に由来する診断追加なし。全体型チェック成功とは報告しない。

追加・変更した検証コードとテストはstrict TypeScript単独チェック成功。関連8ファイル208テスト成功（既存125＋追加83）。新規/更新の旧C# golden、既存MIME18パターン、実更新A、マーカー位置異常・欠落・重複拒否を維持。既存型不整合を回避するため本番のRecordData定義を緩めていない。
