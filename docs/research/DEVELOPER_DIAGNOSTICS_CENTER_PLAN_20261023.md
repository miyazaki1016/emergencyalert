# アメふる 開発者診断センター — 設計台帳 v0.1

更新日: 2026-10-23
状態: 研究設計のみ。未実装・本番未反映。

## 目的
今回のiPhoneホーム画面PWAの通知履歴欄消失を調べると同時に、今後の通知・雨予測・認証・通信障害にも再利用できる、長期運用向けの診断基盤を用意する。

## 原則
- **読み取り専用を基本**とする。診断画面からログアウト、匿名ユーザー作成、地点登録、通知購読変更、DB書き込みをしない。
- 匿名ユーザーID、トークン、Push endpoint、位置座標、登録地点名、通知本文をログに保存・コピーしない。
- 本番利用者には通常非表示。診断を有効化したときだけ詳細イベントを収集する。隠しURLを認証・セキュリティ境界とみなさない。
- 保存容量と期間を制限し、明示的に削除できるようにする。診断データの削除とアプリ認証ストレージの削除は完全に分離。
- iOS Safari / ホーム画面PWAはストレージ領域が異なる可能性がある。診断ログやセッションの共有を前提としない。
- 変更は研究ブランチで検証し、CI・実機テスト・承認を経てから本番へ。

## 診断カテゴリ
1. ライフサイクル: 起動、pageshow/pagehide、visibilitychange、freeze/resume、document再生成、画面部品のマウント/アンマウント。
2. 認証: セッションの有無、匿名IDの継続性（ID本体は保存しない）。匿名IDの同一性比較には既存認証データを改変せず、秘密情報を外部送信しない方法を別途設計。
3. 通知: 権限、Service Worker制御、Push購読の有無、履歴読み込み状態（件数のみ）。
4. 雨予測: 最新取得時刻、結果の鮮度、処理状態、失敗分類。
5. 通信: API応答時間、HTTPエラー分類、オフライン状態。URLに秘密情報が含まれ得るため完全URLを収集しない。
6. 登録地点: 件数と同期状態のみ。
7. 更新: アプリビルド識別子、Service Workerバージョンとcontrollerchange。
8. エラー: JavaScript例外・未処理Promise・React描画エラー。スタックやメッセージには個人情報が含まれ得るため既定で収集しない。

## ログ設計（案）
- 軽量イベントはメモリ内リングバッファ。
- 詳細診断を明示的に有効化した場合のみ、機微情報を除いたイベントをsessionStorage等に短期保持して再生成後も比較する。ただしiOSの復帰・プロセス再生成で保持される保証はない。
- 必要に応じIndexedDB/localStorageの専用名前空間を検討するが、認証キーや既存アプリの保存領域に触れない。
- 各イベントに日時、セッション内連番、イベント種別、ページ起動世代、最小限の安全な状態値を持たせる。
- 画面に「現在の状態」「直前の再生成前の記録」「直近のエラー」「レポートをコピー」「診断ログのみ削除」を設ける。
- 診断の有効化・保存・コピー時には機微情報の混入テストを行う。

## フェーズ
- Phase A: 既存Previewの診断機能に起動世代・短期ログ保持・Service Worker状態を追加。
- Phase B: 本番に導入する診断専用コードを切り分け、テストで既存認証/通知/登録地点への非干渉を確認。
- Phase C: 本番PWAで実機再現し、履歴欄DOMの有無・JS例外・ライフサイクル・認証有無を相関。
- Phase D: 根本原因を修正。診断センターは必要な部分を常設し、詳細収集は既定オフ。
