# MYアメふる — 予測通知の非対称な判定方針（検証用）

## ユーザー方針
- **降りそう：早めに知らせる。** 事前通知のリードタイムと見逃し率を重視する。
- **止みそう：確実に知らせる。** 誤った停止通知と短時間での雨の再開を重く評価する。
- 目的は通知回数を増やすことではなく、意味のある通知の精度を高めること。

## 現状（2026-10-19 のブランチコード）
- 判定エンジン：5 mm/h 以上の降雨、または 1〜5 mm/h の予報が5分刻みで3回続く場合に「行動可能な接近」と判断する。
- 雨の終了予測：雨のある現在地点について、連続3フレームの NO_RAIN があれば ENDING とする。**後続フレームの再降雨や周辺雨域は未評価。**
- watch-rain 通知処理：`RAIN_ENDING` の送信には以前の降雨確認条件などがあるが、観測地点の単一点判定。現地で降っていることの保証ではない。
- 通知履歴には判断根拠を通知IDで固定する仕組みがない。

## 本番変更の前に必要な検証
1. 降り始め：通知から実際の降り始めまでのリードタイム（分）、降り始め見逃し率、空振り率を計測。
2. 止み始め：予測時間内に実際に止んだ割合、いったん止んだ後 15/30 分以内の再降雨率、通知時点で既に降っていない割合を別々に計測。
3. 降り始め通知は時間内の早さを優先。ただし短時間で繰り返す通知は抑制。
4. 止みそう通知は、直近の観測で雨の判定、予報の連続した非降雨、後続の再降雨なし、データの鮮度と欠損なしを候補条件とする。時間窓・閾値は履歴と実際の天気で比較するまで確定しない。
5. 同じ予報に対して旧方式と候補方式の**並行評価（シャドー判定）**を行い、実配信には採用しないまま成績を比較する。
6. レーダーは地表の実際の降雨ではない。ユーザー報告とレーダー観測を区別する。UNKNOWN を晴れとみなさない。

## フィードバックの対応
- `ACTIONABLE_RAIN_APPROACHING`, `RAIN_APPROACHING`, `RAIN_RETURNING`：降った／降らなかった／すでに降ってた／不明。
- `RAIN_ENDING`：止んだ／止まなかった／降ってない／不明。
- `RAINING`, `RAIN_EASING`, `RAIN_CLEAR`, `SEVERE_RAIN_*`：**別途適切な検証設問を設計するまで4択を流用しない**。
- ユーザー回答には、評価した地点・通知時刻・予測対象時刻を表示する。予測期間前に回答する場合は注意喚起。
