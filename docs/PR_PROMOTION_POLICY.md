# PRのmain昇格ルール（初期導入：判定のみ）

## 原則
- 作業ブランチ → PR → CI → 変更分類 → 必要な承認 → main。
- **初期段階は自動マージを無効**。分類結果はレビューの補助情報であり、承認・デプロイではない。
- Draft、変更ファイル一覧の欠落・不完全、未知の変更は自動昇格しない。
- 本体・認証・DB・通知・セッション・デプロイに関係する変更はユーザー承認を要する。
- 管理用スクリプト、CI、ポリシー自身の変更は担当ソラの確認が必要で、自己承認禁止。
- 台帳は人が書いた領域を保護し、機械管理欄の差分が検証できるまで自動昇格禁止。
- GitHubの必須チェック・ブランチ保護・レビュー条件は迂回しない。
- **mainマージと本番デプロイは別の承認対象**。Git連携で自動配備される構成は特に注意。
- 追加のAI API・常駐サービスを使わない。既存Actionsの範囲内で検証する。

## 担当
- GitHub Actions: 機械的な事実・CI・分類。
- プロジェクト担当ソラ: 判断待ちPRの内容・影響を確認し、ユーザーへ報告。
- 自動化担当ソラ: 両リポジトリの分類規則・棚卸し・回帰テストを管理。
- ユーザー: 高リスク変更と例外の最終承認。

## 次の段階に進む条件
実PRで誤分類がないことを確認し、必要なブランチ保護・必須CI・権限・Actions利用枠を検証してから、
**別途ユーザー承認を得て**限定的な自動マージを有効にする。
