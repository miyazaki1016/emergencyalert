# LIVE JAPAN 実データ接続設計（Phase 1 / 未接続）
更新日: 2026-10-16

## 原則
- 現在の LIVE JAPAN は太陽位置演出と架空の表示テストのみ。実際の気象・災害情報を表示していると誤認させない。
- 気象庁などの公式一次情報を優先。情報源・原文識別子・発表時刻・受信時刻・対象地域・有効期限を保持する。
- 取得不能・遅延・解析不能は「情報未取得／確認できません」と表示し、**安全**や**警報なし**と断定しない。
- アプリ上の飾り（桜・紅葉・星空）は災害・天気より低優先。災害情報を地図の操作パネルで隠さない。
- 本番表示・通知・美咲への提供は、別々のリリース判断とする。

## データ経路
1. Provider adapter: 公式フィードから取得。タイムアウト、条件付き取得、レート制限、リトライを実装。APIキー等はサーバー内に限定。
2. Raw ingestion: 元データ・URL・取得時刻・ハッシュを監査可能な形で保存。重複取得は冪等に処理。
3. Normalizer: `app/live-japan/event-contract.ts` の EventEnvelope に正規化。eventId は提供元の安定IDと事象種別を組み合わせる。revision は受信順でなく、提供元の更新順序に基づき決定する。
4. Lifecycle store: issued → updated/corrected → cancelled/expired を同一eventIdで管理。別eventIdの津波情報は地震速報の取消に連動して消さない。
5. Serving API: 現在有効な情報に加え、訂正・取消の履歴、取得状態、最終成功時刻、データ鮮度、提供元を返す。
6. Presentation: 地域別優先順位を適用。対象地域の粒度と地図縮尺が一致しない場合は精度を偽らない。解除は必要に応じて取消済みと明示し、即座に「安全」に変換しない。
7. Future consumers: 美咲等へは安定したサーバーAPIを公開する構想。会話用解釈は提供元事実と区別し、情報鮮度を必須とする。

## 最初の実装順序
- P0: 正式な情報源の利用条件、対象データ（地震・津波・気象警報）の配信仕様、更新/取消識別、地域コード、障害時の扱いを調査し決定。
- P1: 公式ソース1種類だけを**サーバー側**で読み、保存せず隔離したテスト環境で解析。出典・更新日時・エラーを検証。
- P2: 取り込み記録と状態遷移を永続化。順序逆転、重複、欠損、取消、別イベント独立性の自動テストを追加。
- P3: 「実データ（取得時刻つき）」と「デモ」を完全に分離したプレビュー表示。更新失敗時は鮮度切れと明示。
- P4: 地図上の表示位置・重なり・アクセシビリティ・災害時優先表示・モバイルUIを検証。
- P5: 本番リリース判定後に段階公開。通知はさらに別審査。

## 現在の制約と未完了
- EventEnvelope と架空の6ケースは試作段階。実フィードの安定ID/改訂番号/取消表現と一致する保証はない。
- 現状の `applyEventRevision` は型検査の一部のみ。署名・出典検証、ID衝突対策、順序根拠、タイムゾーン厳密性、監査ログ、障害時の振る舞いを強化する必要がある。
- 6ケース合格は架空データの内部ロジック確認であり、公式情報の正確な取得・通知・実災害時の安全性を保証しない。
- 実データへの接続・本番公開・美咲への配信はいずれも未実施。

## 地震情報の表示・通知方針（2026-10-16 合意・実装前）
- **緊急地震速報（警報）** と **観測後の通常の地震情報** は別種別・別ライフサイクル・別の通知判断とする。速報の予測震度を観測震度として扱わない。
- **LIVE JAPAN**：観測された最大震度3以上の地震を全国地図に掲載。震度1〜2は履歴で参照可能とする構想。震度3は黄、震度4は橙、震度5弱以上は赤で強調する（色だけに依存しない）。
- **MYアメふる**：登録地点で観測震度3以上なら通知対象。震度4以上は優先度を上げ、震度5弱以上は強い注意喚起。実装時はユーザーの通知許可・静音設定・地域コードの粒度を尊重する。
- 全国最大震度と登録地点の観測震度を混同しない。地点別の震度が未判明の場合、全国最大震度をその地点の震度として通知しない。「未確認」と明示する。
- **緊急地震速報（警報）** は対象地域で別枠最優先表示。ただしプッシュ通知の速度・到達性・正確性が検証されるまでは、公式の緊急警報手段の代替を名乗らない。
- **津波警報・注意報** は地震の震度や地震速報の取消とは独立して管理する。
- 同一地震の訂正・続報で不必要な重複通知を出さない。ただし重大な震度上方修正・対象地域追加など重要変更は再通知の余地を残す。
- ここに記すのは製品側の初期表示・通知方針であり、気象庁の発表基準そのものではない。実データの仕様と地域単位の確認後に実装する。
