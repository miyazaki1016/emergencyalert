## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
## Summary
- determine forecast completeness from the full JMA forecast series, not only frames whose validTime is still in the future
- keep rain/actionable searches scoped to future frames
- add regression coverage for a cron run 5 seconds after a 5-minute JMA boundary
- preserve INSUFFICIENT_DATA when any forecast frame is invalid

## Why
Production diagnostics showed all 12 forecast frames were valid NO_RAIN, but the first frame was ~5 seconds behind the cron execution time. Filtering it out left 11 future frames, so DRY could never satisfy the old 12/12 completeness check.

No Push decision, notification copy, intensity threshold, or RAIN_ENDING logic is changed.
```
