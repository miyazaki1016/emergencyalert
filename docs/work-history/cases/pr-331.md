+### 1.1 言葉の定義 — 「さきどり」の2つの意味（ユーザー確認 2026-11-28）

+- **先に手に入れる・行う**（他の人より早く自分のものにしたり、行動を起こしたりすること）＝ **楽しみの先取り**。流星群が見える前に知って、予定に入れる。本書の「いいことのさきどり」はこの意味の柱。
+- **予測して先回りする**（これからの流れを読み、時期が来る前に対応すること）＝ **今のさきどりの本体**。雨が降る前に知らせる。キャッチコピー「暮らしを少し先回りする」はこの意味に基づく。

+つまり現行サービスは2つ目の意味だけで構成されており、本構想は1つ目の意味を足すものと整理できる。この対応付けは #327（構想・思想の復元）における原点の定義としても使える。

+## 4. 空のさきどり（重点調査）
+
+### 4.1 暦で決まる型 — 国立天文台（NAOJ）
+
+
+
+- 国立天文台は「ほしぞら情報」（月別の星空・天文現象）と「暦要項」（毎年2月に翌年分を発表）を公開している。暦要項には朔弦望（新月・満月の日時）、二十四節気および雑節、国民の祝日、日出入が含まれる。
+- 満月、流星群の極大、日月食、惑星の接近・最大光度・最大離角、月と惑星の接近は、ほしぞら情報と暦要項で数か月〜1年先まで確定できる。
+- 2026年の目玉は3月3日の皆既月食（全国で見られ、皆既は20時台）。次に同条件で見られるのは2029年とされる（先行設計メモでの NAOJ 展望に基づく整理）。
+
+評価：
+
+- データ源：NAOJ（公的機関）。無料で継続公開されており、年間カレンダーは年1回の整備で確定できる（年30〜40件規模）。再配信は出典明記を前提に、案件化時に NAOJ の利用条件を最終確認する。
+- 予測の出し方：自分たちで予測を作らない。NAOJ の確定情報を「予告→前日→当日」の3段階で早く・分かりやすく届ける。
+- 答え合わせ：当夜の天気実況で「見えたはず／雲で見えなかったはず」を翌日に振り返る（第4.4節）。
+- 既存資産の再利用：ふたご座流星群ページ `/sky/2026-12-14-geminids`（本番公開済み）がこの型の実装第1号。ページ文法は事案ページ（#307）の「予告→当日→振り返り」を継承している。Bluesky 3段階投稿の設計も先行メモで済んでいる。
+- 通知負担：月2〜4件。プッシュ通知は出さず、Bluesky とサイト表示が中心（第11節）。
+
+### 4.2 軌道で決まる型 — ISS とスターリンク
+
+
+
+- ISS（「きぼう」）の目視予報は JAXA が「#きぼうを見よう」（lookup.kibo.space）で公開しており、地域ごとの見える日時・方角・高さが分かる。JAXA は公的機関であり、案内型（JAXA 予報への誘導＋天気の掛け算）なら軌道計算基盤なしに始められる。
+- スターリンク等の軌道要素（TLE／GP データ）は CelesTrak が公開している。原データは米宇宙軍（USSF）の公開データで、CelesTrak はその配信窓口。利用は CelesTrak の usage policy（アクセス頻度の制限など）の遵守が条件で、正式なライセンス文はない。
+- スターリンクの打ち上げ直後の「トレイン」は、運用者提供の Supplemental GP データ（CelesTrak で Starlink 分が公開）から通過を計算できる。ただし通過予測には自前の軌道計算（SGP4）が必要になる。
+- 注意すべき変化：2026年7月に衛星カタログ番号の5桁が枯渇し、新規物体は TLE 形式で取得できないものが出ている。実装時は TLE ではなく OMM（JSON／XML 等）の形式で取得する設計が要る。
+
+評価：
+
+- ISS は JAXA 予報の再利用で早期に実現可能（先行メモでは「軌道計算が要るため後段」としていたが、JAXA 予報の存在により案内型は前倒しできる。これは先行メモへの本書での更新点）。
+- スターリンクは「見たい」層が厚く SNS の目撃共有も多い一方、(a) 軌道計算基盤の新規構築、(b) CelesTrak が「公的機関そのもの」ではなく公的データの配信窓口である点の原則解釈、(c) 打ち上げ予定の監視という発生型運用、の3点が重い。フェーズ後段に置く（第13節）。
+- 答え合わせ：通過時刻の予測は決定的で、検証は「その時刻にその方角で見えたはずか＋当夜の天気」で行う。
+
+### 4.3 発生型 — オーロラ、火球、虹・彩雲
+
+
+
+- オーロラ：NICT（情報通信研究機構）が「宇宙天気予報」を公開し、太陽フレア・地磁気擾乱の現況と見通しを出している。大きな磁気嵐の際には北海道を中心に低緯度オーロラが見えることがあり、2024年5月・10月、2025年11月、2026年1月に観測例がある。ただし日本向けの「オーロラが見える確率」のような予報製品はなく、判断材料は地磁気活動（気象庁地磁気観測所の K 指数など）の水準である。宇宙天気予報自体が「発展途上の分野」と NICT も注意している。
+- 火球：明るい流星の出現は予測できない。予測の対象にはならない。
+- 虹・彩雲・朝夕焼け：定量的な公的予報は存在しない。天気（雨上がり、日射）の結果として起こる現象であり、「今日は虹が出やすい」のような指数は民間の表現に近い。
+
+評価：
+
+- オーロラは「予告」ではなく「今夜はチャンスが高まっている」という発生型の案内に限定する。地磁気嵐の規模が大きい夜だけ Bluesky で短く触れ、見えなかった場合も含めて翌日に振り返る。宇宙天気は通信・測位への影響という安全側面も持つため、楽しみ一辺倒のトーンにしない。
+- 火球は予測対象から外す。流星群の「観測好機」の案内に含めるに留める。
+- 虹・彩雲・朝夕焼けは独立コンテンツにせず、天気コンテンツの文章表現（例：雨上がりの夕方の投稿）の中で触れる程度に留める。
+
+### 4.4 天気との掛け算と答え合わせ（空全体の独自性）
+
+空イベント単体なら天文サイトの方が詳しい。さきどりの価値は「あなたの街で実際に見えるか」まで届けることにある（先行メモ第4節を継承）。
+
+- v1：イベント当日の天気予報（晴れ／曇り／雨の区分）を地域ごとに添える。既存の天気データの読み取りで足りる想定。
+- v2：雲量予報が入手できれば「見えやすさ」を段階表示する。
+- 表現の原則：雲は雨雲レーダーだけでは判定できない（雨を降らせない雲もある）。「見える／見えない」を断定せず、「見えやすそう／雲が多そう」に留め、判定不能は雨の UNKNOWN 原則と同じく正直に出す。
+- 答え合わせ：当夜の実況（天気実況・レーダー）で振り返り、記録を残す。雨の答え合わせと同じく、記録の蓄積が信頼になる。
+
+## 5. 季節のさきどり（重点調査）
+
+### 5.1 気象庁 生物季節観測 — 「観測のさきどり」
+
+
+
+- 気象庁は生物季節観測を1953年から続けており、各気象台のページで観測値（今年・平年・昨年・最早・最晩）を公開している。
+- 2021年1月に対象が絞られ、現在は植物6種目9現象：うめ開花、さくら開花・満開、あじさい開花、すすき開花、いちょう黄葉・落葉、かえで紅葉・落葉。動物（ウグイスの初鳴き、セミの初鳴きなど）の観測は廃止された。
+- 平年値は1991〜2020年の30年平均。観測は標本木に対するもので、「その街全体の見頃」とは厳密には異なる。
+- **さくらの開花予想は気象庁が2009年で終了**しており、現在は民間気象会社のみが行っている。
+
+評価と設計上の工夫：
+
+- 「開花を予想する」ことは原則（公的データのみ）に反するため、さきどりは予想を作らない。代わりに次の3点で「さきどり」を成立させる。
+1. **平年カレンダー**：平年値から「例年ならあと何日で開花」という年間予定を先に出す（暦で決まる型と同じ扱い）。
+2. **観測速報**：気象台が観測を発表したら、その日のうちに届ける。開花・満開はニュース性が高く、速報性で民間の予想とは別の価値になる。
+3. **平年との差の物語**：「今年は平年より9日早い」のように、観測事実に文脈を付けて届ける。事案ページ（#307）と同じ「育つ物語」の文法が使える。
+- 答え合わせ：観測そのものが公的事実なので、検証は「自分たちがいつ届けたか」の記録になる。予想を出していないので外れもない。この割り切りを画面・投稿で明示する（「予想ではなく、観測と平年のご案内です」）。
+- 候補の取捨：藤、菜の花、ひまわり、彼岸花、金木犀は現行の生物季節観測の対象外。蛍も対象外。これらは第5.4節で扱う。
+
+### 5.2 冬の季節現象 — 初雪・初霜・初氷・初冠雪
+
+
+
+- 気象庁は冬の季節現象として初雪、初霜、初氷などを観測し、各気象台が発表している（寒候年＝8月〜翌7月で数える）。
+- 初冠雪は観測方法の移行期にある。従来の目視観測から、アメダス・レーダー・衛星を用いた解析積雪深による情報提供へ移行しつつあり、移行前後の記録は単純比較できないと気象庁自身がしている。
+- 一部地点では初霜・初氷の目視観測・通報が終了している。
+
+評価：
+
+- 初雪は「雪のさきどり」の入口でもある（親サービスでは将来、雨と同じ型で雪の開始・終了・積雪と答え合わせを扱う構想がある）。初雪の観測速報は、その前段として自然に接続する。
+- 初冠雪（富士山など）は写真映えし SNS と相性が良い。観測方法の移行については、記録の断絶を明記して扱う。
+- こちらも「予想」ではなく観測速報＋平年比較の型。
+
+### 5.3 二十四節気・七十二候 — 季節の背骨
+
+二十四節気の日付は国立天文台の暦要項で確定する（翌年分が毎年2月に発表）。七十二候は節気をさらに分けた暦の表現で、日付は節気から機械的に決まる。
+
+評価：コストがほぼゼロで、通年のコンテンツの背骨になる。節気の日に「今日は立冬。例年、初霜が観測され始める頃」のように、生物季節観測・冬の季節現象への導線として使う。単独で通知はしない。
+
+### 5.4 公的データが弱い季節候補（蛍・花火・藤など）
+
+蛍の発生時期、花火大会・祭りの日程、藤・菜の花・ひまわりの名所の見頃は、全国統一の公的データ源が存在しない。自治体・施設が個別に公開する情報は「公的機関の公開情報」ではあるが、形式・鮮度・網羅性がばらばらで、自動収集の設計が重い。
+
+評価：当面は対象外とする。将来やる場合も、全国一律ではなく「特定の名所に絞った手作業カレンダー」に限定すべきである。ウグイス・セミは生物季節観測の対象から外れたため（第5.1節）、観測の正本がない。こちらも対象外とする。
+
+## 6. 景色のさきどり
+
+- **ダイヤモンド富士**：太陽の位置は暦計算で確定できる（日出入・太陽の方位は国立天文台の暦計算の対象）。「どの地点から・いつ見えるか」は地点ごとに計算で決まるため、暦で決まる型として扱える。ただし地点リスト（展望地ごとの日付表）は自分たちで計算して作る資料になる。「データを改変しない」原則との関係では、公表された暦の計算結果の提示であり、観測データの改変ではない、と整理できる。
+- **雲海**：公的な雲海予報は存在しない（民間の宿泊施設・観光地の予報が中心）。原則に照らして対象外とする。
+- **雪景色・夜景**：独立したデータ源はない。積雪の観測（気象庁）と天気の見せ方として、既存の雨／将来の雪の基盤に相乗りさせる表現に留める。
+
+## 7. お出かけのさきどり
+
+祭り・朝市・無料イベントの日程は自治体・主催者の個別公開が中心で、全国統一の公的フィードはない。混雑回避に使う人流データは民間のものが中心である。
+
+評価：5領域の中で原則との摩擦が最も大きい。当面は対象外とし、やる場合も「自治体が公式に公開する年中行事の日程を、地域を絞って手作業で載せる」範囲に限定する。散歩・ドライブの提案は、天気・季節コンテンツの文章表現（例：「今週末は紅葉が見頃の地域が多い」）として内包する方が自然で、独立コンテンツ化はしない。
+
+## 8. 暮らしのさきどり
+
+### 8.1 黄砂（気象庁）— 強い候補
+
+気象庁は黄砂情報を公開している。実況図（過去7日〜当日の観測状況）と予測図（毎日1回、4日先まで6時間ごとの濃度分布予測、約110kmメッシュ）があり、地表付近の分布は「洗濯物の汚れ」の目安としても示される。環境省との共同ページもある。
+
+評価：予測図があるため「明日は黄砂が来る。洗濯物は部屋干しが安心」という、本来の意味での「さきどり」が成立する。洗濯そのものの指数は民間だが、黄砂の飛来予測は公的データであり、その帰結としての生活行動（洗濯・洗車・外出時の注意）は案内文の範囲。既存の気象庁データ接続の延長で実装できる。答え合わせは実況図との照合で可能。
+
+### 8.2 紫外線（気象庁）— 候補
+
+気象庁は紫外線情報を公開している。前日・当日の観測状況と、当日・翌日の予測（約20kmメッシュ、UVインデックス）を1日1回発表し、雲を考慮した予測図と晴天時予測図がある。
+
+評価：翌日までしか出ないため「さきどり」の幅は小さいが、「明日は紫外線が非常に強い」という日々の案内としては成立する。黄砂と合わせて「暮らしの天気派生」としてまとめるのが効率的。
+
+### 8.3 暑さ指数 WBGT（環境省）— 安全側として扱う
+
+環境省の熱中症予防情報サイトが、全国の暑さ指数（WBGT）の実況と予測（3日先まで）を公開し、実況値・予測値のダウンロード（CSV）提供もある。提供期間は例年4月下旬〜10月下旬。熱中症警戒アラートは環境省・気象庁が共同で発表する。
+
+評価：これは「いいこと」ではなく安全情報である。平常時は楽しみ・危険時は安全優先の方針のもと、楽しいコンテンツとは棚を分け、既存の防災・生活安全の流れで扱う。さきどりの地図レイヤーに載せる場合も、雨や警報と同じ「安全側」の見せ方にする。
+
+### 8.4 花粉 — 原則に照らして対象外とする判断案
+
+
+
+- 環境省の花粉観測システム「はなこさん」（全国120地点の自動観測）は **2021年に終了** し、国は花粉の自動観測から撤退した。
+- 気象庁は花粉飛散予測を行っていない。現在の飛散状況・予測は民間気象会社（自動観測機のネットワークを持つ事業者）が担っている。
+- 環境省・林野庁はスギ雄花の調査データなどを民間に提供しているが、リアルタイムの飛散量そのものの公的観測は存在しない。
+
+評価：花粉は生活ニーズが非常に大きいが、「公的機関の公開データだけ」の原則に照らすと、届けるべき中核データ（飛散量の実況・予測）が公的に存在しない。原則を曲げて民間データに乗るのではなく、**対象外とする**のが一貫した判断である。将来、自治体の観測公開が広がるなど状況が変われば再評価する。
+
+### 8.5 感染症（国立健康危機管理研究機構／国立感染症研究所）— 週次の「流行の山」案内
+
+感染症発生動向調査の週報（現在は急性呼吸器感染症サーベイランス週報など）が毎週公開され、インフルエンザ等の定点当たり報告数が都道府県別に分かる。厚生労働省も発生状況を公表している。
+
+評価：週次データなので「さきどり」の速報性はないが、「自分の県で流行が立ち上がってきた」という山の入口の案内はできる。健康情報は表現の責任が重い。断定的な助言はせず、公的発表への誘導に徹する。優先度は低く、やる場合も Bluesky の週1回の定点観測的な投稿に留める。
+
+### 8.6 その他の暮らし候補
+
+- 洗濯指数・服装指数：これらは民間気象会社の指数であり、公的データではない。対象外。ただし「雨が降る前に洗濯物を取り込む」は既存の雨の基盤で既に実現している領域であり、新規コンテンツは不要。
+- 換気・快適な夜・凍結：独立した公的指数はない。気温・湿度・天気の文章表現に留める。
+- 旬の食べ物：公的な統計（水揚げ・出荷）はあるが、当面は対象外。
+- 電力需給：需給ひっ迫の注意報・警報は政府発表の仕組みがあるが、本書ではデータ源の詳細を確認していない。安全側の情報であり、扱う場合は別途調査する。
+- 交通：渋滞・混雑の公的リアルタイムデータは限定的（道路の規制情報は公的だが「お出かけの楽しみ」とは性質が違う）。対象外。
+
+## 9. 画面設計（LIVE JAPAN との接続）
+
+
+
+- **地図レイヤー**：トップの日本地図に「空・季節」の小さなレイヤーを足す。常時表示は「次の空イベント」カード（例：「3月3日 皆既月食まで あと◯日」→直前は「今夜 20時ごろ皆既」）に留め、地図の主役（雨・安全情報）を邪魔しない。危険情報があるときはそちらを優先する（憲章の原則どおり）。
+- **年間カレンダー「空と季節の予定」**：月別に並ぶ一覧ページ。暦で決まる型（空イベント・節気・開花平年など）を一望できる場所にする。
+- **イベントページ**：事案ページ（#307）と同じ文法（予告→当日→振り返り＝答え合わせ、専用 OGP、恒久 URL）。空は `/sky/<日付>-<slug>`（ふたご座ページで採用済み）。季節は観測の物語ページとして、自治体×季節現象の単位が候補（例：その街の桜の開花→満開の記録）。
+- **MY 接続**：登録地点について「あなたの街では今夜見えやすそう」「あなたの街の桜は平年あと◯日」という個別化は、表示の個別化に留め、プッシュは第11節の条件を満たす場合だけ。
+
+## 10. SNS 設計（予測→体験→共有）
+
+既存方針（Bluesky＝全量の本拠、X＝精選の看板）をそのまま使う。
+
+- 空イベント：3段階投稿（1週間前の予告／前日リマインド／当日夕方の「今夜だよ＋地域別の見えやすさ」）。リンク先はイベントページ。翌日に答え合わせ投稿を足し、4点セットにすることを提案する。
+- 季節：観測速報はその日のうちに1投稿。平年カレンダーの節目（節気の日、開花平年の1週間前など）は軽い予告投稿。
+- 体験→共有：目撃・撮影した利用者の投稿を紹介する（リポスト等）のは「共有」の範囲として可。ただし利用者の報告を観測データとして集計・表示することは「自分たちでデータを作る」ことに近づくため、線引きとして行わない。
+- 大規模イベント（皆既月食クラス、初雪の広域観測など）は X にも精選して出す。
+- トーン：災害系と切り替える。怖がらせず、「今夜、空を見上げる理由」「季節が一歩進んだこと」を届ける。安全情報（暑さ指数・黄砂の健康注意など）は楽しみのトーンに混ぜない。

+## 11. 通知設計（通知負担の原則）
+
+不要な通知は出さない。具体化すると：
+
+- 空・季節コンテンツは原則プッシュ通知しない。届け先は Bluesky とサイト表示（フィード型）。
+- 例外は MY 登録者のオプトインのみ：登録地点で見られる旗艦イベント（皆既月食級）について、当日リマインドを最大1回。頻度上限は月1回程度を目安とする。
+- 安全情報（大雨、暑さ指数の警戒級、黄砂の濃い飛来など）は既存の安全側の通知方針に従い、楽しみ系の通知枠とは混ぜない。

+- 役割分担：さきどり＝「何が・いつ・見えるか」の正本。美咲＝それを日常会話の温度で伝える表現層。
+- 美咲側の「今日の出来事」の材料として、節気・空イベント・観測速報は相性が良い（その日の会話のきっかけになる）。ただし連携の実装は美咲側の進行（実経路の一周）が優先で、本書では接続点の宣言に留める。

日本列島を主役にした、日常でも見たくなるインタラクティブなトップ。コンセプトは「日本の今と、少し先の未来。」「暮らしを、少し先回りする。」。

- **平常時**：地図と昼夜・季節の穏やかな表現。太陽位置に基づく日照演出等はすでに試作あり。飾りを気象観測と誤認させない。
- **変化があるとき**：日本全国の実際の気象・防災情報を地域別に表示。危険情報を季節・演出より優先し、出典・発表時刻・鮮度・予測／実況の別を明示する。
- 地図から地域・警報を選択して詳細へ移動。大雨であれば全国大雨予報の詳細や**時刻付き雨雲アニメーション**へ接続する構想。
- 「これまで・いま・このあと」の時間表現は試作済み。ただし**現時点で実時系列データは未接続**。
- 地震・津波・気象警報などを扱う長期構想。緊急地震速報（秒単位の予測）の独自再配信は既存方針上、対象外。
- 原型の正本：PR **#61** `feat/live-japan-experience-prototype`、`app/live-japan/page.tsx`、`docs/LIVE_JAPAN_REAL_DATA_INTEGRATION_PLAN.md`。**既存試作を改めて作り直さずに評価・再利用**する。

## 2. アメふる：二つの雨関連コンテンツ

### 2-A. MYアメふる
- 利用者が地点を登録して、その地点の雨の降り始め・変化を見守り、必要時に通知する。
- 重点品質は**誤報と見逃しを減らし、予測対象時刻と実際の観測の意味を分けて検証すること**。通知の重複抑制、信頼性、ユーザー体験を優先。
- MYアメふるの地点別**30mm/h以上の重要通知**と、後述する**全国無登録の大雨一覧**は異なる配信・表示目的。混同しない。

### 2-B. 全国大雨予報 — アメふるの原点／最重要の実現希望
- **全国のどこかで、今後30分以内に30mm/h以上の雨が予測される地域**を、誰でも地点登録なしで一覧表示する。旧Xでの全国大雨予報投稿のWeb版。
- 地名、予測時刻、予測強度を確認でき、**選択した地域で気象庁の予測画像を時刻順に再生し、雨雲がどう近づき強まるかが分かる**ことが最も実現したい体験。
- 歴史的に旧アメふるは**アニメーションGIFを生成**し、X/Twitter側の表示時にMP4へ変換されていた。**旧システムがMP4を生成していたとは書かない**。
- アニメーションの時刻は実際の公式予測の有効時刻。AIによる架空の雨雲運動や未来フレームの創作をしない。
- 旧X: https://x.com/_emergencyalert ; 参照投稿: https://x.com/_emergencyalert/status/1663129832178487296/photo/1
- 旧運用では大雨以外に土砂災害・洪水・ダム放流・暑さ指数・不審者等も投稿していた。これらは**親サービスの歴史**であって、すべてをアメふるに入れる確定仕様ではない。

- **データを削除・上書きしない。** 容量節約は依存関係・運用実測・代替案を評価してから。現行使用の有無と将来の重要性は別問題。

**当時の雨雲アニメーションを含む投稿：** [旧X投稿・画像](https://x.com/_emergencyalert/status/1663129832178487296/photo/1)。旧アメふるがGIFを生成し、Twitter/X側の表示時にMP4へ変換したという原型の動作を、将来の動画再現の基準とする。
