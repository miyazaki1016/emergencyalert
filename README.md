# EmergencyAlert 2026

> 暮らしを、少し先回りする。  
> 必要な人に、必要な情報を、必要な時に。  
> 必要でなければ、静かに見守る。

## 原点

「おかあさん、そろそろ雨降ってくるよ。洗濯物しまったほうがいいよ」

EmergencyAlert は、情報を大量に配信するためのサービスではありません。
正規に発表された情報から、その人の場所と時間に関係する少し先の変化を見つけ、
**今どう動けばいいか分かる形で伝える**ことを目指します。

## 大原則

**EmergencyAlert は天気を予測しない。**

気象庁など正規に発表された予報・観測・防災情報を正本とします。
独自に気象現象・発生時刻・降水量・危険度を予測、補間、改善しません。

AI を使う場合も役割は、公式情報の要約・説明・生活文脈への変換までです。

### データ判定の原則

1. 分からない ≠ 雨なし
2. 欠損を勝手に補間しない
3. 公式情報から言える範囲だけ言う
4. 「雨なし」≠「安全」
5. 通知する価値がなければ静かに見守る

### 通知・事実確定の原則

**予測は早さ優先、結果は確実性優先。**

- 「降りそう」「止みそう」は未来予測なので、公式データから条件を満たした時点で早めに案内する。
- 「降った」「止んだ」は観測結果なので、5分間隔の判定を3回連続で確認してから事実として確定する。
- 「降った」は3回連続 RAIN で確定し、同じ降雨エピソードでは1回だけ通知する。
- 「止んだ」は3回連続 NO_RAIN で確定する。Pushは増やさず、内部状態・画面表示に使う。
- 同じ降雨エピソードでは「止みそう」は1回だけ通知し、3回連続 NO_RAIN でエピソードを終了して次の雨に備える。


## Phase 1 — アメくる？2026

最初の完成目標は現在地について、

- 今は降っていない
- このあと生活上知らせる価値のある雨が予報されている
- 雨が弱まりそう／降水のない予報が続きそう

を、気象庁の公式情報に基づいて分かりやすく伝えることです。

初期の生活通知閾値は **5 mm/h 以上が30分以内** を候補とします。
これは気象学的な危険基準ではなく、EmergencyAlert の生活通知用の初期設定値です。

小雨だけなら原則通知しません。降り止みについては、単発のゼロではなく、
連続した有効な公式予報を確認してから案内します。

## Phase 1-A の範囲

DB、Push通知、AI生成はまだ入れません。

```
Browser Geolocation
  -> JmaRainProvider
  -> OfficialRainFrame[]
  -> RainInterpretationEngine
  -> UI / Developer View
```

Developer View では、issue time / valid time / tile / pixel / raw RGBA /
raw state / intensity / source を追跡可能にします。

## 開発原則

旧 EmergencyAlert (2023) は思想と試行錯誤を知るための参考資料であり、仕様書ではありません。

**思想は継承する。実装は検証する。**

現行の公式仕様・公式データを確認して実装します。
